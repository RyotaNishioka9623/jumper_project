## 3. 評価基準

### 3.1 明示されている基準

**配点: 視聴者の反応 60% + 専門家審査 40%**

| 評価軸 | キーワード | 対応する成果物 |
|---|---|---|
| Appearance（外観） | Beautiful | `.skin`（外装デザイン） |
| Motion（動き） | Playful | 学習済みポリシー / `.app`（ダンス、ジャンプ、ジェスチャーなど） |
| Skills（技能） | Useful | 実用的な振る舞い（把持、運搬、センサーを使った行動など） |

- 「どれか1つの軸で突出すれば十分。複数の軸で優れていれば加点」
- 「アイデアの共有、デバッグ、失敗談も当選の可能性を高める」 → **制作過程の発信そのものが評価対象**
- 「面白く目立つ作品は KingKong が実機で再現する場合がある」
- 「100の優れた**オープンソースプロジェクト**を選ぶ」 → GitHub での公開が前提と考えるべき

### 3.2 規約上の必須条件（守らないと失格や問題になり得るもの）

- **オリジナリティ**: 盗用や第三者IPの侵害は失格。既存キャラクターの外装は避ける
- **音楽の権利**: 楽曲は提供されない。権利処理済みのBGMを自分で用意する（自作またはライセンスが明確なフリー素材）
- **利用許諾**: 応募作品は KingKong に対し、永続的・非独占的・商用利用可の権利を許諾する扱いになる
- **ライセンス遵守**: 公式ツールキット（Apache-2.0）と NOTICE の条件に従う
- **誇張しない**: シミュレーション結果を実機で検証済みとは表現しない（公式ドキュメントも明記）

### 3.3 暗黙の評価基準（配点構造からの推論）

**視聴者の反応（60%）を取るために**
1. 冒頭2〜3秒で引き込む（Xは自動再生。最初の絵で決まる）
2. 一目でわかるコンセプト（説明なしで面白いもの）
3. シリーズで投稿する（制作過程、失敗集、完成版。期間中に複数回露出）
4. 日英併記（国内の拡散と海外の審査員の両方に届く）

**専門家審査（40%）を取るために**
5. 公式ツールキットを正しく使っている（`.skin` / `.map` / `.app` の正式フォーマットで出力）
6. 再現性（GitHubにコードやデータと手順がある）
7. 実機で再現できそうか（関節制限やトルクの範囲内、転倒しない）
8. コミュニティへの貢献（他の人が使える道具やデータ）

## 4. 技術的に実現できること（リポジトリ調査より）

| 領域 | 仕組み | 使える手持ちの環境 |
|---|---|---|
| 外観 | jumper-design で `.skin` を作成（新しい形状は外部のモデリングツールが必要） | **Blender** |
| シーン | `.map`（`kk-scene-package`）。リプレイ用の背景には使えるが、学習には使えない | Blender |
| 新しいダンスやジェスチャー | 関節角度とベース姿勢を記録した `.npz` から、BeyondMimic 方式の模倣強化学習を行う。既存例: `dance_*`, `gesture_bow` など | **Blender でキーフレームを作り** → **Colab GPU** で学習 |
| 歩行やジャンプ | PPO + MuJoCo Warp（`jumper.tripod`, `jumper.jump` など） | Colab GPU |
| 動画 | `scripts/play.py --video` / `scripts/export.py` で MP4 を出力し、音楽を合成 | Colab |

制約:
- スキンは表示専用で、学習には読み込めない
- 任意のマップでの学習は未実装
- 実機推論（RKNN）は公式でも未検証

Jumperのハードウェア（`docs/HARDWARE.md` より、表現に関係するもの）:
- 4本の脚で立ち、2本の前脚（ハサミ付き）を腕のように使える（既存の手を振るジェスチャーと同じ構成）
- 表情用の丸型カラーディスプレイ×2（目）、スピーカー×2、マイク×4
- 5MPカメラ、dToF深度センサー、NPU 6 TOPS

## 5. 制作の方向性：テーマから決める

決める順番: テーマ → キャラクター → シチュエーション → 必要な動き → 外観とシーン

テーマ候補（当初の「侍ガニ」案は、見た目だけの設定で動きと結びつかないため不採用）:

| 案 | 内容 |
|---|---|
| **A. 照れ屋のカニ（採用）** | ハサミで顔を隠す、チラ見する、照れて横歩きで逃げる |
| B. ペットのようなカニ | 出迎える、お手をする、ごはんを催促する |
| C. 健気で不器用なカニ | 何度も挑戦して失敗する |
| D. 横歩きしかしたくないカニ | カニらしさを誇張したコメディ |

## 6. X投稿の方針（決定）

日本語版と英語版の2投稿に分ける。

- **英語版を正式な応募投稿にする**: 必須のハッシュタグとメンションを付ける
- **日本語版は英語版の引用ポストにする**: 日本語圏の反応を応募投稿の閲覧数と引用数に集める
- 視聴者の反応（60%）が投稿ごとに集計されると、2投稿に分散して不利になる可能性がある。上の形で応募投稿に集約する

## 7. 決定コンセプト：「チョキしか出せないカニ」

> じゃんけんが大好きな照れ屋のカニ。ハサミなのでチョキしか出せず、グーに負けてはしゅんとする。
> パーに勝つと、喜んだあとに照れてハサミで顔を隠す。

- 英語の一言フック: *"This crab can only throw scissors ✂️🦀"*
- じゃんけんは海外でも Rock Paper Scissors として通じるので、言葉の説明がほぼ不要

### 評価軸との対応

| 評価軸 | 対応する要素 |
|---|---|
| 動き（Playful） | じゃんけんの振り、チョキ、しゅん、照れ喜び |
| 外観（Beautiful） | 目のディスプレイの表情（キラキラ、涙目、照れ）。外装は控えめで、例えば頬の赤み程度 |
| 技能（Useful） | 第2段階：カメラで相手の手を認識し、勝ち負けに応じて自動で反応するインタラクティブ版 |

### 絵コンテ案（第1弾、約25秒）

| 秒 | シーン | 動き | 目の表情 |
|---|---|---|---|
| 0–3 | 構え（テロップ「チョキしか出せないカニ」） | ハサミを構えて体を弾ませ、やる気満々 | キラキラ |
| 3–6 | じゃん・けん・ぽん | ハサミを3回振り、チョキを出す | 真剣 |
| 6–10 | 相手はグー → 負け | 体を沈め、ハサミをだらんと下ろす | 涙目 |
| 10–16 | 気を取り直して再戦 → また負け | しゅんの動きを繰り返し、2回目はさらに深く沈む | 涙目 |
| 16–20 | 3回目、相手がパー → 勝ち | 一瞬固まる | 驚き |
| 20–25 | 照れ喜び | 小さく跳ねて喜ぶ → 我に返ってハサミで顔を隠す → 隙間からチラ見 | 照れ（頬の赤み） |

### 決定事項（2026-10-14）

- **路線**：「本物のロボットで本気で実装した」方向
  - 「カニはチョキしか出せない」は定番のジョークで、2DのGIFで投稿した例もある
  - 差別化の軸：22自由度の実モデルでの強化学習、感情のあるリアクション、本当にじゃんけんできるインタラクティブ版、Blender振り付けツールのOSS公開
  - 投稿の切り口：*"Everyone jokes that crabs can only throw scissors. So we trained a real 22-DoF crab robot to play rock-paper-scissors."*
- **アニメーションは結果別に3本**：負け `janken_lose`、勝ち `janken_win`、あいこ `janken_draw`
  - それぞれ「構え → じゃん・けん・ぽん → チョキ → 結果へのリアクション」までを含む1本のクリップ
  - 最後に動画編集で1本にまとめる
- **音**：声は入れない。テロップと効果音だけにする（効果音は自作か、ライセンスが明確な素材）
- **サムネイル**：グーを出している手に、チョキで挑んでいる場面
- **注意**：X の @jumpercrabsol は公式ではなく、暗号資産トークンの宣伝アカウント（プロフィールにコントラクトアドレスあり）。メンションも引用もしない

### 必要なモーション

公式のジェスチャー（`gesture_hello` など）と同じく、立ち姿勢（HOME）から始まり HOME に戻る形式にする。

| タスク | 内容 | 状態 |
|---|---|---|
| `jumper.janken_lose` | 振り×3 → チョキ → グーに負けてしゅんとする | デモ版（全工程の確認用） |
| `jumper.janken_win` | 振り×3 → チョキ → パーに勝って弾んで喜ぶ → 照れて顔を隠す | 未着手 |
| `jumper.janken_draw` | 振り×3 → チョキ → 相手もチョキ（反応は検討中） | 未着手 |

技術的な制約：
- 変換時の胴体姿勢は「常に床に接地している」前提で計算する。空中に跳ぶ動きは表現できないので、喜びは弾む動きで表す
- 前脚を上げると顔の前を覆う形になり、照れて顔を隠すポーズとして使える

### 未確定事項

- **チョキの見せ方**：開いたハサミがカメラから見えるポーズ、腕の向き、カメラ位置
- **目の表情**：シミュレーション映像では目のディスプレイが黒い板のまま。表示方法を決める
- **相手の手**：サムネイルと本編に出すので、3Dの手を置くか実写を合成する
- **あいこのリアクション**
